# Generated-canary helper containment design - frozen plan

1. Reconcile the accepted vault threat model with current controller,
   supervisor, runtime-profile, and mock-vault sources.
2. Specify a separate signed native parent/helper topology, exact inherited-FD
   contract, sterile environment, limits, and anonymous mock-sink protocol.
3. Specify conservative audit and crash semantics with a durable release gate
   before mock-sink delivery.
4. Define deterministic falsifiers for network, subprocess, arbitrary-file,
   inherited-FD, output, core, timeout, and ambiguous-outcome behavior.
5. Seal the design and submit the immutable packet to an outside design
   council.
6. Stop at `ACCEPT_DESIGN_ONLY` or the first blocking correction. Do not build
   or spawn the helper in this run.

Acceptance requires a council-reviewed, claim-bounded design whose first
implementation slice uses generated data only and cannot be mistaken for
Keychain, provider, or real-secret qualification.
