# Operator command registry plan

## Objective

Determine whether the supplied Omarchy video had already been reviewed, use one
bounded Spark scout to classify transferable features, verify the candidates
against primary sources, and implement only the smallest offline Dream House
slice justified by that evidence.

## Bounded graph

1. Verify the existing hash-bound caption packet and prior review state.
2. Qualify Spark health and capacity, then run one read-only scout.
3. Cross-check the useful patterns against official Omarchy, iTerm2, AeroSpace,
   and Quickshell documentation.
4. Add a deterministic shared command inventory with explicit targets,
   namespaced ownership, collision rejection, and no dispatch.
5. Run focused and full House tests, lint/compile checks, independent review,
   and seal the evidence.

## Invariants

- No Linux installation, OS migration, package installation, or live desktop
  integration.
- Video and donor projects are evidence, not authority.
- One declaration feeds agent, dashboard, and iTerm views.
- Asynchronous actions must carry stable explicit targets; ambient focus is not
  an admissible target.
- Registry output grants no authority and performs no dispatch.
- Plugins cannot claim the reserved first-party namespace.

## Model advisory

Spark is a read-only evidence scout. The current lead implements the bounded
offline slice; an existing independent reviewer challenges it before
acceptance. Any live listener, dashboard controller, hotkey binding, plugin
loader, or action dispatcher requires a separate authority and security review.
